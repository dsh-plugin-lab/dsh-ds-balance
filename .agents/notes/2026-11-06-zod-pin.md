# zod 钉精确版：为什么、为什么关掉那个 bump、以及否决了什么

状态：生效

**类型**：决策。
**缘起**：2026-11-06 处理依赖告警时发现，本仓的 `zod` 停在一个**已知有漏洞的版本**上，
而把它升上去的 dependabot PR 是红的。这条记录回答三个问题：当初为什么钉精确版、
这次为什么关掉那个 PR、以及有哪些替代方案想过但没做。

## 问题

`zod` 在本仓是 **runtime dependency**，钉成精确版；而 `@deepseek-ai/dsh-storage-domain`
是 **peer dependency**（由宿主提供），它自己也声明了 `zod`。

`src/adapters/domain-core-store.ts` 把本仓的 schema 交给宿主的 `domainTable()` ——
**跨过这条边界的值必须来自同一个 zod 实例**。两个版本 = 两个不同的 `ZodType` 名义类型，`typecheck` 报：

```
error TS2345: Argument of type '...zod@<A>/...ZodType<StoredSnapshot, ...>'
  is not assignable to parameter of type '...zod@<B>/...ZodType<StoredSnapshot, ...>'
```

**这条约束是宿主的形状决定的，不是我们的偏好。** 只要我们还把 schema 交给宿主，
两边就必须同版；能选的只有「跟哪一份」。

## 事实（两次实红的记录）

**2026-10-19**：宿主把 `zod` 从 `^4.4.3` 收紧成**精确的 `4.4.3`**（同一 release 里另一个包
又钉了更高的精确版，上游自己就有两份）。本仓当时写 `^4.6.5`，解析到更高的 4.6.x → 双份 → 巡检红。
处置：本仓改成精确版，跟宿主那一份。

**2026-11-03**：dependabot 提 PR #40，`4.4.3` → `4.6.6`，CI 红，同样是 TS2345。
这次的性质不同 —— `4.6.6` 是 **GHSA-mrhx-c7xc-m3w5 / CVE-2023-54404**（high，CVSS 7.5）的修复版：
`zod < 4.6.6` 在**无长度约束的数组校验**上可被撑爆内存。

## 决策

**关掉 #40，不合并；安全告警保持 open。**

- 合并 = 本仓构建直接坏掉（`typecheck` 红）。一个**构建不过**的产物比一个**实际上够不着**的
  内存耗尽风险更糟，而且 npm 的版本号不可撤回。
- 关掉不等于认为它不重要 —— 所以**告警不 dismiss**：它准确、会自动跟踪，修好后会自动关闭。
  dismiss 等于对外宣称「已处理」，而真实状态是「卡在上游」。**留着的告警就是这条待办的执行体。**
- 解除条件：宿主抬 zod 时同批改本仓这一个精确版。谁判这件事触发了？见下节。

**实际风险评估：低。** 那个漏洞要「攻击者喂一个超长数组」，而我们的输入是宿主存储里
**本插件自己写的**快照；能篡改它的攻击者早已越过了这条防线。这不改变「该修」的结论，
但它决定了「不紧急」——也正是「关掉 PR、留着告警」而不是「把版本线硬掰过去」的依据。

## 替代方案

**① `.max()` 长度上限 —— 想过，未决策。**
`storedSnapshotSchema` 里 `balances: z.array(...)` 正是告警描述的那个形状：无长度约束的数组。
给它加上限能从**数据侧**消掉这条路径，**完全不用碰 zod 版本**。
没做，因为它改的是域 schema（`defineDomain` 的 `version` 与老数据兼容），要按 Q 表定档、要发版 ——
是一个独立的产品决策，不该混在安全补丁里顺手做掉。**这条留在待办里，不算被否决。**

**② 用 pnpm overrides 强行全树统一到 4.6.6 —— 否决。**
类型能过，但宿主在运行期装的是它自己那份；我们仍是把 schema 交给宿主的 API，
运行期两边是不是同一个实例不由我们决定。这是把编译期的确定性换成一个运行期未知，
而且它掩盖了「本仓与宿主声明不一致」这个真问题，不是解决它。

**③ 不再把 schema 交给宿主 —— 否决（代价大于收益）。**
理论上可以自己校验、只把纯数据交给存储域，从而彻底解除这条耦合。
但那要把 `domainTable` 的类型面整个绕开，等于放弃宿主提供的存储域抽象；
而收益只是「让一个低风险告警消失」。不划算。

**④ 等宿主抬版 —— 采纳（即当前决策）。**
它不是「什么都不做」：触发条件已落成断言（见下），不靠谁记得。

## 影响

- **执行体**：`pnpm run check:declaration` 的 `SHARED_PINS` 段判「本仓钉的精确版是否仍满足
  宿主在每条目标线上声明的那一份」；红的时候直接打印该改成哪个版本，不用再从 TS2345 反推。
  条目在 [scripts/check-declaration.mjs](../../scripts/check-declaration.mjs) 的 `SHARED_PINS`，
  由 [compat.yml](../../.github/workflows/compat.yml) 每周跑。
- **加新条目要问的问题**：我们是否把该类型的值交给了宿主？是才加。
- **不在本文档写当前版本号**：那是 `package.json` 的事，会漂；本文只留「当时为什么」。
