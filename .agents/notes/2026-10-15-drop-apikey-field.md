# 连接组重做成只读状态：删 `apiKey` 与 `baseUrl`、掩码放宽到首尾片段

状态：生效

**类型**：决策。
**缘起**：维护者指出官方 0.2 把模型卡的凭据 UI 重做了一轮（`deepseek-harness` 的
`7110b615eb`「生成提供方元数据并显示凭据检测状态」：独立的 `ApiKeyInput`、placeholder 三档、
框下四态检测行、Base URL 提示），要求本插件「跟随着改」。对照之后发现：**我们与那个 key 的关系
是「跟随者」而不是「所有者」**，所以该抄的是它的**语义**（把「生效的凭据从哪来」说清楚），
不是它的控件。

## 问题

连接组当时是一列输入框：一个继承官方、不可改的只读凭据框 + 可编辑的 `baseUrl`
+ 二级「自定义设置」里的 `apiKeyRef`。逐项问「它有没有使用场景」之后：

- **`apiKey`（配置字段）**：界面上从来没有填它的入口，它只剩一个作用 —— 手改
  `settings.yaml` 的人可以**静默压过**官方那份凭据。而它的优先级**高于**凭据服务与环境变量
  （`KeyResolver` 的第一档），界面读的 `credentials.describe()` 又**看不见**它。
  于是它会让「凭据来源」展示**说假话**：显示「未配置」，而插件正拿那份 key 在跑。
- **`baseUrl`（配置字段）**：本插件的职责就是绑定官方，端点没有第二个合法取值。
  **不能**改成跟随官方的 `DEEPSEEK_BASE_URL` —— 那个变量是 **Messages 根地址**
  （`https://api.deepseek.com/anthropic`），而余额端点在根域下（`GET {root}/user/balance`），
  照抄会拼出 `.../anthropic/user/balance`。契约 §3.2「端点独立」说的就是这件事。
- **`apiKeyRef`（界面入口）**：默认值 `DEEPSEEK_API_KEY` 就是官方那一个，99% 的人不需要改。
  它**保留在 schema 里**（读凭据存储的哪一条是个真输入），但不再上界面。
- **「测试连接」按钮是假的**：它做的是本地字符串检查 + `setTimeout(800ms)` + 「连接正常。」，
  **一次网络请求都不发**；而后端那个真端点 `POST /api/v1/test-connection` 已经写好、也有用例守着，
  客户端一处都没调它。

## 决策

1. **删 `apiKey`**（schema 11 → 9）。解析链变成 `credentials.resolve(apiKeyRef)` →
   `process.env[apiKeyRef]`，这正是「跟随官方」的字面实现。
2. **删 `baseUrl`**，端点变成常量 `ENDPOINT`（= `DEFAULT_BASE_URL`，官方根地址）。
3. **`apiKeyRef` 留在 schema、退出界面**：它不构成假话（状态展示**跟着它读**，不像 `apiKey` 绕开 `describe()`）。
4. **连接组改成只读状态展示**：两条途径各一行（API Key / 账号登录），
   配一个**真打上游**的测试按钮；二级「自定义设置」连同它一起删（它只剩一个字段，而那个字段也没了）。
5. **掩码放宽到首尾片段**：`sk-cf08d*****3b84`（前 8 + 固定 5 个星号 + 后 4），
   形态与 DeepSeek 平台控制台 `platform.deepseek.com/api_keys` 一致。
   **完整密钥永不跨线**：后端解析出明文后立刻折成掩码再丢掉。
6. **判据搬到后端**：新增 `GET /api/v1/sources`，两条途径的状态一次给全。
   客户端从前那套四档判定（`use-credential-state.ts` 的 `credentialViewOf`）删除。
7. **后端订阅 `credentials/reference-updated`**，作废状态缓存 —— 这是对
   [2026-09-30-credential-change-refresh-boundary](2026-09-30-credential-change-refresh-boundary.md) 第 1 条
   **「不订阅」的有意反转**（那条已标「被取代」），理由见下。

## 替代方案（想过，为什么不选）

1. **照抄官方的可编辑密钥框**（write-only + 眼睛显隐 + placeholder 三档）。
   不选：那整套建立在「这个框归你填」之上，而我们的凭据归官方模型页或启动环境 ——
   抄过来就是又一格假控件。官方那张卡片自己的措辞也承认这点
   （`keyPlaceholderSaved` = "Leave blank to use saved credentials"）。
2. **保留 `apiKey` 字段、只是界面上不再摆它。** 不选：**留着它，新界面就是错的** ——
   隐形覆盖会让「凭据来源」显示与实际生效值不一致。要修的是那个不一致，不是把入口藏起来。
3. **`baseUrl` 改成跟随 `DEEPSEEK_BASE_URL`。** 不选：那个变量是 Messages 根地址，
   拼法不同（见上）。照抄会打出错误的路径。
4. **掩码保持固定长度 `********`。** 不选：它回答不了「我现在用的是哪一把 key」——
   而「换 key 之后余额不对」正是这个插件最容易遇到的困惑。
   放宽的代价（真 key 的 10 个字符进浏览器）是**可接受**的：前缀本身不构成凭据，
   平台控制台自己就是这么显示的。
5. **掩码只露前 8 位、不露尾**（与官方 `ui-secret-mask` 的 `VISIBLE_PREFIX = 8` 一致）。
   不选：那个常量服务的是**聊天记录里的密钥遮罩**（把对话文本里的 key 打码），
   不是设置页展示凭据；而首尾形态的辨识度更高，且与平台控制台一致。
6. **给账号与 Key 两张卡片都画头像，做成对称。** 不选：**账号那条才有身份** ——
   官方 `AccountProfile`（名字 / 头像 / 脱敏联系方式）只存在于账号侧，
   API Key 是一串没有身份的字符串。硬给 Key 画一个头像那是装饰，不是信息。
   两行靠**状态点对齐**，所以少了头像也不歪。
7. **客户端 `inject remote` 直接订阅官方事件。** 不选：要多挂
   `@deepseek-ai/dsh-api-remotes` 依赖，并同批改全部 23 条声明面与 `engines.dsh` ——
   为一个状态展示动整条声明面，代价不对等。改为**后端订阅 + 客户端在
   「挂载 / 窗口重新获得焦点 / 点测试」三个时机重读**，覆盖全部真实流程。
8. **把 `sources` 也做成事件推送（SSE）。** 不选：凭据是低频变化的东西，
   而卡片是低频界面；轮询或推送都只是白烧请求。

## 影响

- **破坏性变更（major，2.x → 3.0）**：手改 `settings.yaml` 写过 `apiKey` 或 `baseUrl` 的部署
  **静默失效**（前者掉到凭据服务/环境变量，后者回到官方地址）。两份门面同批给出迁移说明。
- **契约放宽**：`http/AGENTS.md` 那条「`apiKey` 的任何片段都不许进响应体」改成
  「只回首尾掩码，永不回完整密钥」；`apiKeyMasked` 字段从 `GET /api/v1/config` **移除**，
  掩码改由 `GET /api/v1/sources` 的 `key.masked` 承担。
- **代价（已知并接受）**：走内网镜像 / 自建代理的部署失去了唯一的变通办法 ——
  端点从此不可配，只能等我们支持（或改代码）。
- **能力回收**：界面不再提供任何「填密钥」或「改地址」的入口；
  两件事都只能在官方模型页 / 环境变量 / `settings.yaml` 里做。
- **观测出口**：`GET /api/v1/sources` 的 `revision`（凭据世代）是「有没有东西换了」的唯一判据；
  `GET /api/v1/healthz` 的 `source` 仍是「此刻服务的是哪条路」。
- 反转本条时：新写一条记录并把本条状态改为「被取代」。
